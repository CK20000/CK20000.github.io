STM32H743 Betaflight Flight Controller — Bare-Metal Port

WHAT IT DOES

Custom Betaflight target files and a 4-layer carrier board that enable standard Betaflight firmware on a generic industrial STM32H743VIT6 devboard. Where commercial flight controllers restrict you to pre-configured layouts, using a bare industrial devboard opens up full control of the silicon — at a fraction of the cost.

The project is packaged as a definitive architectural guide: porting rules, timer remapping for advanced multi-rotor and actuator configurations, and fixes for three silicon-level bugs that block boot on this specific H743 variant.

WHY IT'S PUBLIC

Unlocking full silicon control for the hobbyist and researcher community beyond pre-configured commercial flight controllers. Every fix documented as a reproducible recipe, not a one-off.

THE PROBLEM

Betaflight's H7 codebase is optimized for 8 MHz or 24 MHz crystals on commercial FC hardware. The DevEBox board uses a 25 MHz HSE, and its silicon behaves differently in three separate ways that all block boot or peripheral initialization. Each failure looks unrelated; all three must be fixed for the target to be usable.

BUG 1 — 25 MHz HSE / PLL1 VCO OVERFLOW

Applying the default STM32H7 PLL multipliers to a 25 MHz HSE pushed the internal VCO to 3000 MHz, exceeding the 960 MHz hardware limit. The PLL engine fails, which triggers an infinite safety reset loop inside HandleStuckSysTick() — the board never reaches the main loop.

Fix: Rewrote the pll1ConfigRevY / pll1ConfigRevV clock structures to scale the 25 MHz crystal safely to a stable 480 MHz SYSCLK (M=5, N=192, P=2).

BUG 2 — DEAD HSI48 BLOCKS USB ENUMERATION

STM32 USB peripherals need a 48 MHz clock. Betaflight tries to enable the internal HSI48 oscillator to generate it. On this specific H743 revision, RCC_CR_HSI48ON register writes are silently ignored — the oscillator never starts, USB fails to enumerate, and the virtual COM port is dead.

Fix: Bypassed the dead HSI48 circuit entirely. Synthesized a 48 MHz USB clock from the working 25 MHz HSE via the PLL3 engine (M=5, N=48, Q=5), gated behind a custom USE_USB_CLOCK_PLL3 macro.

BUG 3 — DUAL BMI160 DMA COLLISION

With two BMI160 gyroscopes on SPI1 and SPI2, the secondary gyro regularly failed to lock its DMA channel. Two separate issues compounded:

  • The H7 DMAMUX auto-allocator was already claiming DMA1 Stream 0 for DSHOT_BITBANG_1, starving SPI1_TX of a continuous stream. Result: silent fallback to CPU-polling mode, missing the dma flag downstream.
  • The driver code (pios_bmi160.c) used a global BMI160InitDone boolean. When Gyro 1 initialized, it set the flag; Gyro 2 skipped its configuration logic entirely on cold boot.

Fix: Hardcoded explicit DMA stream offsets in config.h (bypassing DMAMUX auto-allocation) and refactored the driver to remove shared global state, so each BMI160 instance configures independently.

WHY THIS MATTERS

Each bug is documented with the exact register, the exact symptom, and the exact fix. Anyone porting Betaflight to a non-reference H7 board can follow this recipe instead of rediscovering it from a bricked board.

CARRIER BOARD

  • 4-layer PCB, through-hole DevEBox H743VIT6 soldered to SMD pads
  • 8 through-hole alignment pads for the devboard, reducing assembly complexity
  • Breakout pads for BMI160 and BMP280 GY-modules — pluggable, no dedicated routing needed

SENSOR TOPOLOGY

  • Primary IMU: BMI160 on SPI1 (PA4 CS, PA5 SCK, PA6 MISO, PA7 MOSI, PC4 EXTI)
  • Secondary IMU: BMI160 on SPI2 (PB12 CS, PB13 SCK, PB14 MISO, PB15 MOSI, PD10 EXTI)
  • Barometer: BMP280 on I2C1 (PB8 SCL, PB9 SDA, address 0x76)

BLACKBOX & STORAGE

  • SDIO MicroSD slot (SDMMC1) with software card detection
  • QSPI external flash W25Q64JV (64 Mbit) for high-rate blackbox logging

ACTUATOR LAYOUT

  • 8 motor outputs: PA0–PA3 (M1–M4), PB0–PB1 (M5–M6, timer remapped), PD5–PD6 (M7–M8)
  • 4 servo outputs: PE5–PE6 (S1–S2), PE1 & PA15 (S3–S4, timer remapped)

SERIAL & TELEMETRY

  • UART1 (PA9/PA10) — Serial RX
  • UART3 (PD8/PD9) — ESC Telemetry
  • UART6 (PC6/PC7), UART7 (PE7/PE8) — general telemetry / VTX expansion
  • Beeper output on PC2 (inverted)

POWER & ADC

  • GM V1.0 power module integration: V_SENS on PC1, I_SENS on PC0 (16-bit ADC)
  • Baseline scaling: vbat_scale=108, current_meter_scale=85 — must be calibrated per-module with a bench multimeter
  • AMS1117-3.3 LDO fed from an external 5 V rail, robust down to a 4.4 V sag threshold

CLOCK CONFIGURATION — THE CRITICAL FIX

// pll1ConfigRevV — scale 25 MHz HSE to 480 MHz SYSCLK
pllConfig_t pll1ConfigRevV = {
    .clockMhz = 480,
    .m = 5,      // 25 MHz / 5 = 5 MHz reference
    .n = 192,    // 5 MHz × 192 = 960 MHz VCO (within limit)
    .p = 2,      // 960 MHz / 2 = 480 MHz SYSCLK
    .q = 8,
    .r = 5,
    .vos = PWR_REGULATOR_VOLTAGE_SCALE0,
    .vciRange = RCC_PLL1VCIRANGE_2,
};

USB CLOCK — BYPASS DEAD HSI48

// config.h
#define USE_USB_CLOCK_PLL3

// system_stm32h7xx.c — synthesize 48 MHz from HSE via PLL3
PLL3M = 5,   // 25 MHz / 5 = 5 MHz
PLL3N = 48,  // 5 MHz × 48 = 240 MHz VCO
PLL3Q = 5    // 240 MHz / 5 = 48 MHz USB clock

// config.h — override DMAMUX auto-allocation
#define DEFAULT_GYRO_TO_USE  GYRO_CONFIG_USE_GYRO_BOTH

BUILD

git clone --recurse-submodules https://github.com/betaflight/betaflight.git
# copy DEVBOARD/ target into src/config/configs/
# patch system_stm32h7xx.c + pios_bmi160.c
make clean
make DEVBOARD -j$(nproc)

FLASHING

Enter DFU mode by shorting BT0 to 3.3 V (pins near the SWD header), then flash the built .hex via STM32CubeProgrammer or the Betaflight Configurator.
